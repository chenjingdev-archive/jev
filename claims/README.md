# 제작자 벤치마크 교차 실행 — 결과 (2026-10-01)

Jev-like 제작자는 저마다 자기 벤치마크로 성능을 주장한다. 그 벤치마크를 모두 모아 32세트 14,113문항으로 만들고, 15개 시스템을 같은 계약으로 돌렸다. 처음 19세트(10,233문항)는 2026-09-28~29에, Nimble이 내세운 13세트(3,880문항)는 2026-09-30~10-01에 더했다.

- 모든 시스템은 `choose(state, instructions, criteria)` 하나로만 불린다. 보기 순서를 최대 5가지로 바꿔 부르고, 확률을 평균해 답 하나를 정한다.
- 실행 전 조건과 세트별 출처는 `PROTOCOL.md`, 세트를 만드는 코드는 `build.py`·`build_ext.py`·`build_jeff.py`·`build_nimble.py`에 있다.
- 모델별로 잘하는 것과 못하는 것은 `PROFILES.md`에 정리했다.

## 수치 읽는 법

- **정확도:** 세트 안에서 맞힌 비율이다. 시스템이 받지 못한 문항(처리 못 함)은 오답으로 센다. 세트 평균은 세트마다 같은 가중이다.
- **받은 문항만:** 처리 못 한 문항을 빼고 낸 정확도다. 세트를 통째로 못 받았으면 그 세트는 평균에서 빠진다. "못 받음"과 "못 품"을 나눠 보려는 열이다.
- **표시:** `*`는 일부 문항, `×`는 세트 전체를 처리하지 못했다는 뜻이다. `†`는 같은 분포 학습이다(평가 문항과 겹치지는 않지만 같은 데이터셋의 학습 split으로 학습했다). 굵게는 세트 1위이고, 동률이면 모두 굵게 했다.

## Nimble이 발표한 수치와 비교

Nimble은 `docs/PUBLIC_BENCHMARKS.md`에서 이 13세트로 Nimble과 Jev를 맞댔다. 같은 레코드를 썼지만 조건이 다르다.

- **Nimble 발표:** 원래 순서로 한 번 불렀고, 원래 형식(noul은 P(true), score는 단계 고르기) 그대로였다. Nimble은 CUDA에서 합친 체크포인트로 돌렸다.
- **우리:** 보기 순환 평균이고, 모든 형식을 보기 고르기로 바꿨다. Nimble은 Ollama Q8_0이다.

## 처리 못 함

## 해석의 한계

- noul은 [false 설명, true 설명] 두 보기로, score는 다섯 단계 설명을 보기로 바꿨다. 보기에는 설명만 넣고 키 이름(`SUPPORTS`, `"0"`~`"4"` 등)은 뺐다. Nimble 평가에서는 Jev가 키 이름을 보고 noul을 원래 형식으로 받았다.
- Nimble·Tev1은 Ollama 배포본(Q8_0 GGUF)으로 돌렸다. 제작자가 발표 수치를 낸 정밀도와 다르다.
- d1은 버전 해시도 가중치도 없는 API다. 이 결과는 2026-09-30~10-01에 부른 `d1:free`의 값이고, 나중에 부르면 달라질 수 있다.
- 세트 평균은 크기가 100~2,000문항으로 다른 세트를 똑같이 센다. 1위 세트 수는 동률을 모두 1위로 셌다.
- McNemar는 문항을 서로 독립으로 본다. 한 세트 안에 비슷한 문항이 많으면 실제보다 작게 나온다.
