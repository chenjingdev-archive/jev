# 판 표기 비교와 이어지는 학습 — 사전 고정 (2026-10-02, 결과 보기 전)

`PROTOCOL.md`(사목 1,000건 학습)에 이어지는 실험이다. 그 실험에서는 학습 손실이 내려가지 않았다. 학습 전 Jeff는 판을 읽지 않고 거의 늘 "아직 없음"을 골랐다(`README.md` 사후 분석). 이번에는 판을 적는 방식이 병목인지 본다.

## 1. 표기 (`represent.py`)

판의 내용, 규칙, 질문, 보기는 그대로 둔다. state의 "판"과 "표기" 문장만 바꾼다.

| 표기 | 내용 | 대상 |
|---|---|---|
| grid | 원래 격자 (첫 실험과 같음) | 사목·오목 |
| coords | `X: B2, C2, …` / `O: A2, B4, …` (위에서 아래, 왼쪽에서 오른쪽 순서) | 사목·오목 |
| stacks | `2열: X X X O` (열마다 맨 아래부터) | 사목만 |

계산된 사실(이기는 자리, 줄 길이 등)은 어느 표기에도 붙이지 않는다. 같은 판을 다른 순서로 적을 뿐이다.

## 2. 단계 1: 학습 없이 표기 비교

- **시험 문항:** `PROTOCOL.md`의 시험 T(사목 500)와 N(오목 300)이다. 표기만 바꾼 `test/items-coords.jsonl`, `test/items-stacks.jsonl`을 쓴다.
- **시스템:**
  - 학습 전 Jeff-0.8B(`jeff-0.8b-torch`, amd)
  - Jev(`jev-1.13.0`, API)
  - grid 결과는 이미 있는 `c4test`를 쓴다.
- **비교:** 같은 시스템에서 grid와 각 표기를 같은 문항끼리 McNemar로 비교한다(양측).
- **"의미 있음"의 기준:** coords나 stacks 가운데 하나라도 다음을 만족하면 단계 2로 간다.
  - 두 시스템 중 하나에서 T 또는 N 정확도가 grid보다 높다.
  - 그 차이가 p < 0.05다.
- **학습에 쓸 표기:** 기준을 넘은 표기가 둘이면, 학습 전 Jeff의 T 정확도가 더 높은 쪽을 고른다. 같으면 오목에도 쓸 수 있는 coords를 고른다.

## 3. 단계 2: 고른 표기로 학습 (기준을 넘었을 때만)

- **본 학습:** 첫 실험과 같은 학습 데이터 1,000건과 설정을 쓴다. lr 1e-5, 3 epoch, 10스텝마다 dev 손실로 체크포인트를 고른다. 학습 데이터, dev, 시험을 모두 고른 표기로 바꾼다. 결과 모델은 `jeff-0.8b-c4-1k-<표기>`다.
- **판정:**
  - H1(사목 시험 T)과 H2(오목 시험 N)는 `PROTOCOL.md`와 같다.
  - 기준선은 학습 전 Jeff에 **같은 표기**로 준 결과다.
  - grid로 학습한 `jeff-0.8b-c4-1k`와의 비교는 참고로 적는다.
- **외우기 점검 (진단):** 학습 문항 100개만으로 lr 5e-5, 10 epoch를 돌린다. 같은 100개로 정답률을 잰다. grid와 고른 표기에서 각각 한 번씩 돌린다.
  - 이 점검은 학습 설정으로 학습 데이터를 외울 수라도 있는지 보는 진단이다. 가설 판정에는 쓰지 않는다.
  - 학습 문항 정답률이 90% 이상이면 "외웠다"고 적는다.
- **결과 기록:** 결과는 어느 쪽이든 그대로 쓴다. 기준은 결과를 본 뒤 바꾸지 않는다.
